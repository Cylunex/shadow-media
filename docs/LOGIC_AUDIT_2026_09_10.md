## 2. 已修复的具体问题

### 影视和来源

- Feed 删除当前影片前面的条目时，旧实现沿用原索引，会指向后一部影片。现在优先保留当前媒体 ID，再计算新索引；删除当前条目时才选择其后继。
- 视频线路失败时，旧回退固定 `playWhenReady=true`。现在继承用户的暂停/播放状态。
- 视频上报原先每次独立启动 IO 协程，慢请求可能令 STARTED、PAUSE、STOPPED 入库顺序颠倒，退出还会取消未处理的旧任务。现在在每个播放器内按回调顺序串行发送，关闭后处理完剩余记录再释放报告任务。
- 集成服务探测返回时，原先把整个旧连接列表写回页面，能重新显示已删除的连接。现在取消被替代的探测，只把仍匹配的连接结果合入最新列表；网络存储使用相同的存活检查。
- 网络存储移除时清掉内存连接和后端引用。已打开的文件句柄按原播放器生命周期关闭，不声称可以撤销服务器端正在进行的读取。
- 外部 Provider 从搜索页直接播放后，返回目的地原先固定成详情页。现在返回实际发起页面。
- 外部播放的凭据隔离现在使用明确来源或实际初始 URL，并同时处理 API Key、MediaBrowser 与 Emby 头；Range 保留。路由 DataSource 补齐响应头和 SMB 传输监听转发。

### 直播与下载

- 回看模板的月份 `{m}` 和分钟 `{M}` 使用大小写不敏感替换，导致分钟被替换成月份。现在按模板字面大小写替换。
- EPG 的旧预算包在 gzip 输入外侧，实际限制的是压缩字节。现在分别限制压缩输入和解压输出，解压后最多 96 MiB。
- `.gz` 路径配合 HTTP `Content-Encoding: gzip` 时，OkHttp 已经解码，旧代码会再次解压。现在以内容头识别实际 gzip，兼容已解码正文和无 `.gz` 后缀的 gzip。
- 节目单请求取消会取消对应 HTTP Call，避免离开页面后继续下载。
- 整文件下载拒绝 206 部分响应；SMB 读取校验已知剩余长度。截断文件删除本次临时副本，不进入书库。

### 阅读、漫画与听书

- TTS 的可取消任务在初始化等待前登记。初始化期间停止或退到后台不会在稍后开始朗读；每次 speak 使用独立请求 ID，迟到回调不能结束下一段。
- 普通漫画最后一页和最后一个双页可以标记完成；长图需要最后一页到达底部，能完整显示的短图直接视作到底。PDF 沿用分页完成规则。
- 音频暂时无法建立进度会话时清除占位状态，继续播放期间允许重试，避免永久卡在“已建立”的假状态。
- 替换音频队列前先保存当前快照，再读取续播位置，减少退回上一周期记录的问题。
- 本轨结束睡眠同时处理单曲循环产生的 REPEAT 转场；追加队列检查总条目上限。
- 播放错误后按钮可以重新 prepare/play；重复条目切换会重置拖动中的进度值。
- Emby 重复播放可能直接复用缓冲、不重新解析 URL。结束后保留有界的会话绑定，使新一轮播放能继续上报；重复的结束快照保持幂等。
