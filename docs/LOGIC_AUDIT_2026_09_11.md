# 2026-09-11 逻辑走查与修复

基于 `7094733` 复查请求生命周期、缓存与个人状态边界、音频恢复和发布验证。三轮分别检查正常/异常路径、并发与取消、修复后的状态合并和 CI 触发行为。只使用本机测试与模拟数据，没有修改真实来源账号或服务端数据。

## 修复

| 触发场景 | 原问题 | 处理 |
| --- | --- | --- |
| 已显示缓存详情，远端刷新尚未完成时翻页 | 两个任务争用内容请求引用，刷新可能覆盖追加页 | 刷新期间禁止分页；离开页面推进请求代次，旧结束回调不再更改加载状态 |
| 分页同步完成或页面字段在等待期间更新 | 依赖 Job 赋值时序收尾；合并使用请求开始时的旧详情 | 以请求代次收尾；基于当前详情追加并去重，重试清除旧错误；按钮置于目录末尾 |
| 目录数据库读失败或缓存写入失败 | 网络请求被阻止，或成功结果被旧缓存替换 | 三类目录统一按可选快照处理；失败保留原快照，成功网络结果直接交付，取消异常继续传播 |
| 错把另一账号的 MediaKey 交给缓存 Provider | 缓存详情可按相同 itemId 返回本 Provider 的条目 | cachedDetail、cachedBrowse 与 browse 统一检查 Provider 身份 |
| 同一个音频队列实例并发打开/刷新 | 重复解析可覆盖候选、回退索引或刷新标记 | 同键解析串行；刷新采用最新回退索引，仍限制每实例一次过期刷新 |
| Service 关闭时解析仍在途或排队 | 迟到结果重新写入会话，过期候选继续上报 | 关闭状态禁止后续解析与写回；选择只接受当前实例的实际候选 |
| 从音乐队列恢复服务 | 初始化与应用恢复队列仍可能保留 SPEECH 属性 | 初始化、恢复和模式切换均按 MUSIC / SPEECH 设置音频属性 |
| Feed 实验关闭、退后台、网络断开或列表改变 | 无用监听/轮询；同一索引遗留多个旧预载 | 关闭即释放回调和池；前台才轮询；确认实际非计费网络；相邻 ID/续播位置变化取消旧准备，同一索引仅保留一个预载 |
| 网络存储凭据暂时无法解密 | 启动注册 Provider 和来源页面可能抛出未处理异常 | 页面显示错误、保留密文，其他来源照常注册；刷新/移除失败不清理连接引用 |
| Emby 解密失败后移除单个账号 | 空回退被当成真实空列表，可能清掉所有账号密文 | 与保存相同地拒绝写入；删除落盘失败明确报告，UI 保持现有账号状态 |
| 普通 Git 推送 | 旧 CI 自动打 APK，且未接入新发布源码门禁 | push/PR 只做验证；手动 `build_apk` 才打包；增加当前迁移链、依赖和 NOTICE 门禁 |

缓存容错仅用于可重建元数据，不应用于收藏、进度、凭据、已安装文件或其他权威状态。账号存储测试注入真实 AES 密钥及内存 SharedPreferences；生产仍使用原 Android Keystore 别名与 AES-GCM 布局，没有迁移密文格式。
