# 媒体记忆与洞察

Shadow Media 把“记住一个画面”和“理解播放质量”作为同一条本地观看数据链处理。所有记录均保存在
Room 数据库中，不上传到推荐服务，也不把 Emby 凭据复制进记录。

## 媒体时刻

普通 Media3 播放和内置 ISO 播放底部控制区都提供“保存时刻”。记录包含 Provider、媒体 ID、标题、
当前毫秒位置和创建时间。进入“设置 → 媒体记忆”后可以从该位置继续播放，也可以单独删除。

时刻按 Emby 服务器与用户隔离。如果当前登录与记录所属 Provider 不一致，应用只提示切换服务器，
不会尝试把一台服务器的媒体 ID 发送给另一台服务器。

## 用户片段

播放过程中可把当前位置标记为片头终点，或者标记为片尾起点。片段以媒体 ID 和 Provider 为作用域
持久化；再次播放进入片段区间时，控制区会显示“跳过片头”或“跳过片尾”。当前版本不会自动 Seek，
避免错误标记干扰观看；用户可在媒体记忆页删除当前媒体的片段标记。

数据模型同时预留前情回顾、预告、精彩片段、章节，以及来自 Emby 章节或服务端分析的来源类型，
后续可在不改变播放器接口的前提下接入可靠的片段识别结果。

## 可解释推荐

首页“现在就看”只使用已经加载的 Emby 首页内容，通过续播状态、收藏、未看状态和社区评分进行本地
排序。标题直接说明排序依据，既不产生不可解释的画像，也不向第三方发送观看历史。

## 播放洞察与脱敏导出

媒体记忆页聚合最近的播放样本：平均首帧、缓冲次数和时长、失败数量及线路健康度。分享诊断时只
导出计数、时长、播放方式分布和线路数量，不包含：

- Emby 或外部服务地址；
- 媒体标题、媒体 ID 和 Provider ID；
- Token、Cookie、Authorization 或请求头；
- 完整播放 URL、host 或线路标识；
- 单条错误正文。

因此导出结果适合用于定位整体播放体验，但不能代替需要用户明确授权的抓包或服务端日志。

## 通勤听与选定素材

在当前模块的工具菜单打开「通勤听 · 已下载」，选择可用分钟数。列表按原速区分本次能听完、可先听一段和时长未知，每组选出最多三项。已开始的听书与播客按本机位置续播，音乐沿用从头播放习惯。进入列表会核对实际下载缓存，或核对系统本地存储中文件的可读性。已完成听书、过期或残缺下载和移除的来源不会当成可用候选。通勤队列保留离线约束，副本失效时可以回下载页补存。

个人助手可给出 `shadowmedia://commute?minutes=20`。分钟数允许 1–180 的整数。本人在装有 Media 的 Android 设备点开后，由该设备按当前已连接来源、音频进度与文件状态生成列表，选中一项才播放。链接自身只带时长，助手无须持有书库或音频访问凭据。

在 Novel 的「书签与摘录」中分享一条摘录，或在「媒体记忆」中分享一个影视时刻，系统分享面板会预填标题、所选片段或时间点和一条原处链接。阅读摘录使用 `shadowmedia://saved/quote/<UUID>`，影视时刻使用 `shadowmedia://saved/moment/<UUID>`。返回链接依赖原设备的本地记录、对应书库连接或当前影视账号。原件已删除或来源不可见时显示不可用。分享正文可用于个人札记草稿。返回位置由本机记录 ID 解析。
